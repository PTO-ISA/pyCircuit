# TMU.TUL.FLS — 冲刷

- 源候选项：`DAV-TMU-TUL-FLS-0001`
- 硬件层次：**H3**，位于 H1 `TMU` / H2 `TUL`
- NDF 细化：**L2 微架构**；模块级 L1 行为链接仍需评审。
- 建议处置：**别名**（提议，尚未获目录批准）
- 实现位置：使用 `designs/davincioo/` 下获准的包含所有者或契约文件；此目录处置不授权独立叶节点。
- 当前设计计划执行状态：**别名；没有实现，也不该有**。下面列出的所有者就是实现记录。

遗留的标量 T/U 恢复名字；实现所有权已经移交给 SPE.OOO.FLS，TMU 不得再获得标量状态。

## 这个名字原本指什么

冲刷就是推测被判定错了之后发生的事：某个点之后的工作全部丢弃，机器恢复成原来的样子。这个
候选项给 T/U 寄存器命名了这件事。

## 现在这件事归谁

| 步骤 | 所有者 | 它干什么 |
| --- | --- | --- |
| 标量恢复 | [SPE.OOO.FLS](../../spe/ooo/fls.md) | 丢弃标量工作，恢复标量重命名状态 |
| 该退到哪 | [TMU.TRN.CHK](../trn/chk_CN.md) | 存着捕获的 frontier，回答恢复要退多远 |
| 撤销 tile 名字 | [TMU.TRN.RAT](../trn/rat_CN.md) | 从新到旧弹自己的历史栈，一次一条 |
| 撤销 tile 空间 | [TMU.TRN.FRE](../trn/fre_CN.md) | 取消预留，空间原样还回来 |
| 撤销 tile 状态 | [TMU.TRN.STS](../trn/sts_CN.md) | 删掉推测行，且碰不到已发布的行 |

一次波及 Tile 状态的冲刷，是以普通 TMU 事务的形式打在这些所有者身上的，**不是**通过一个
TMU 冲刷所有者。这个区别不是措辞问题：每个所有者都会拿自己的代际再校验一次这次恢复，所以
陈旧的恢复是被"本来会被搞坏的那一家"拒绝的，而不是靠一个必须被信任的中央权威。

## 为什么 TMU 不能拥有它

TMU 里的冲刷所有者得知道正在丢弃哪些标量工作，而那是 [SPE.OOO.FLS](../../spe/ooo/fls.md)
的状态；它还得去改兄弟模块的状态来完成撤销，而这在设计计划里是明令禁止的：
[chk_CN.md](../trn/chk_CN.md) 记着，连专为恢复而存在的 CHK 都从不写 RAT、FRE、STS——它只
回答一段距离，让每个所有者自己执行回退。

## 如果你是找到这儿来的

- 冲刷**标量**状态：[SPE.OOO.FLS](../../spe/ooo/fls.md)。
- 恢复 **tile** 状态：先问 [CHK](../trn/chk_CN.md) 要目标 frontier，再按这个距离向
  [RAT](../trn/rat_CN.md) 发相应次数的回退；同时在 [FRE](../trn/fre_CN.md) 里取消还挂着的
  预留、在 [STS](../trn/sts_CN.md) 里回退推测行。
- 注意目前**没有任何东西**给这三件事排序，[chk_CN.md](../trn/chk_CN.md) 把这个缺席的协调者
  列为未决项。

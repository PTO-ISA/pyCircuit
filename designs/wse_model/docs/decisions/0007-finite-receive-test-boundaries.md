# 0007. 有限接收测试模型的容量与身份边界

- **Status**: accepted
- **Date**: 2026-11-03
- **Design sources**: Calendar §4.5.2；原 Python `ReceiveAccount` / `CoreIngress`
- **Code**: `models/calendar/receive.py`、`receive_checks.py`、`wse_model.calendar.receive_encoding`

## Context

Python 核心的去重集合没有容量上限。迁移测试模型使用有限去重表，原草稿在
表满时等待空间，但空间只在完成后退役时释放，可能形成永久等待。设计未规定
片段序号宽度；草稿使用的 16 位属于测试载体。

## Decision

用户明确选择：新到达的有效、已提交、非自身且未见过的片段需要去重记录，
但没有空间时，报“模型容量不足”并停止运行，保留此前状态。用事务断言
`WSE_MODEL_CAPACITY: dedup identity slots exhausted` 实现；它与 WSE 协议故障
分开，不返回普通背压状态。重复、自身、未提交片段沿用原核心分支，无需新槽。

测试输入转换使用 `encode_segment`。当前载体限定 40 节点、8 位轮次、16 位
序号。保留可表示的原整数，拒绝越界，禁止截断、取模或重新编号。重复身份
继续交给核心去重；不同来源的相同序号是不同身份，新上下文可以复用身份。
调用者应传入完整原始序号；若上游已经自行回绕成旧身份，单靠该身份无法区分
“新片段错误复用”与合法重发，转换器不承诺判断这种意图。

## Consequences

本决定限定消费者测试模型，不改变无界 Python 核心，不给 WSE 硬件规定去重
容量或包头宽度。决定接受时，完整接收后端验证仍等待上游 #378，独立断言
测试仅验证容量检查及失败发布边界。

2026-11-03 执行状态更新：参数化循环已在本地修复，完整接收模型的直接到达
与缓冲接纳容量耗尽场景均已通过两个后端的预期失败检查。外部原始 Request
还需容纳保留操作码等协议反例，因此输入驱动直接校验同样的整数与布尔边界；
普通合法 Segment 的转换入口仍为 `encode_segment`。

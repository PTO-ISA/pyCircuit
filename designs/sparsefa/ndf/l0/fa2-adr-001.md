# FA2-ADR-001：分块精确注意力的加速器目标 {#FA2-ADR-001}

<!-- ndf: kind=decision modality=must refinement=L0 status=bringup owner=flash_attention2 -->

## 目的

定义 FlashAttention2 加速器必须保持的算法结果和存储目标，为后续 L1 行为合同与 L2
微架构选择提供边界。本条款只规定架构意图，不选择具体 tile 尺寸、PE 数量、SRAM
bank、流水级或片上互联。

## 架构意图

加速器接收逻辑张量 `Q`、`K`、`V` 以及缩放和 mask 配置，计算注意力输出 `O`。对每个
batch、head 和 query 行，结果必须与选定数值 profile 下的参考定义一致：

```text
S[i,j] = scale * dot(Q[i,:], K[j,:]) + mask(i,j)
P[i,:] = softmax(S[i,:])
O[i,:] = sum_j P[i,j] * V[j,:]
```

硬件可以按 key/value 分块处理，并在块之间保留足以恢复同一 softmax 结果的行状态；
它不得要求把完整的 `S` 或 `P` 矩阵写入片外存储才能完成一次前向计算。分块顺序、
重算策略和内部缓存组织属于 L2 决策，但不能改变上述可观察结果。

## 必须保持的性质

- 对相同输入、配置、初始状态和数值 profile，输出与独立参考 Oracle 的误差必须在
  profile 声明的范围内；不能用候选硬件输出反推 Oracle。
- mask 对禁止位置的语义必须明确，并且禁止位置不能对有效输出产生非预期贡献。
- 任意合法的分块边界都不能造成漏算、重复计分、重复累加或行归一化状态错配。
- 片外流量和片上容量可以随实现变化，但实现必须能说明其工作集、回压和完成条件；
  不能把未定义的无限缓冲区当作设计前提。
- 失败、取消、复位和重新启动时，未提交的中间状态不能污染下一次独立调用。

## 首个 profile 的建议范围

下面内容是进入 L1 前需要确认的起点，不是本条款已经冻结的硬件参数：

- 推理前向计算；
- FP16/BF16 输入，FP32 累加；
- 显式 `scale`，默认值可由上层按 `1/sqrt(D)` 提供；
- non-causal 与 causal 二选一或同时支持的二值 mask；
- 暂不把 dropout、反向传播、稀疏模式和 KV cache 作为首个闭环的必要条件。

若首个 profile 采用其他精度、mask 或训练语义，必须在 L1 中写出独立的数值和状态合同，
不能只修改这段建议文字。

## 明确不在本条款内决定的内容

`D`、`S_q`、`S_k` 的范围，张量物理布局，tile 大小，片上存储层次，PE/矩阵单元数量，
内存带宽，时钟目标，片上网络，命令格式，队列深度，仲裁算法和具体 pyCircuit 模块
接口均留给后续条款。它们只有在不改变本条款的外部结果和失败语义时，才能作为 L2 选择。

## 下一条直接细化

下一份 L1 应把一次调用的接受条件、输入/输出生命周期、mask 结果、数值容差、反压、
取消、复位和完成事件写成可观察合同，并明确首个 profile 的具体维度与 dtype。

## 当前冻结范围

本条款的算法目标、分块计算目标、禁止完整 `S/P` 片外物化、操作隔离和失败不污染后续
调用，作为当前 FlashAttention2 设计基线冻结。冻结不等于 `accepted` Golden：L1/L2
仍需独立评审，L3 仍需 generated-DUT 证据；任何发现的算法矛盾必须先暂停下游晋级，
不能通过修改 Oracle 或实现输出来消除。

# 字段依赖与有界条件生成

纯组合结构体是信号的分组。把 `control.stall` 传给一个标量接口，应按 stall 字段的来源分析，
不能把 Control 其他字段的普通载荷就绪条件全部附加给消费者。传完整结构体仍要求全部输入就绪。
显式断言、调用 guard、事务原子性以及资源读取视图属于独立约束，字段投影不能删除这些约束。

前端自动生成的“所有路径都返回”检查使用内部 `check_kind="return_coverage"` 标记。
它验证相应返回值的可用性，不把未连接字段的普通 Signal 就绪条件变成整个记录的显式断言。
用户写出的 assert 和 Rule guard 继续作为必须保留的约束；没有标记的历史断言按显式断言处理。
该标记随 Source IR 序列化，不需要用户新增注解。

事务提取中的值摘要保留组合 struct/tuple 的成员就绪条件和生产者信息，经过参数、别名、导出、
嵌套字段、结构化分支合流及静态字段更新传播。资源读出的完整载荷保持不透明，沿用资源读取快照；
动态更新等不能证明的情形保留完整条件。修改性 Rule 的生产者标记递归覆盖返回载荷的成员，
禁止借字段投影绕过独立事务之间的普通返回值约束。

公共 `acir-project-fields` pass 将静态字段投影解析为原有 SSA 来源，穿过 bind/export、
构造、select 和静态字段更新，不克隆原算术计算。条件选择保留选择条件，无法解析的叶子保留
字段读取。投影缓存限定在当前基本块，生成的值支配所有复用位置。
正常编译及 Source/Transaction IR 重载都在事务阶段执行此归一化；它不依赖 Python 临时对象。
条件分析、C++ 和 RTL 生成及解释执行因此看到相同的字段数据依赖。独立 acir-opt 管线可显式使用此 pass。

保留结构体与解析字段来源是两件事。仍被整体使用的聚合值、资源、类型和流水 payload 都保留，
不要求在前端把所有结构体拆散。默认 Ripes5 模型无需修改。

## 条件排序失败时

需求条件依赖可能有环，而真实 SSA 数据依赖仍无环。C++ 后端检测这种环后，不再递归复制
每条路径的依赖，而是按数据 DAG 生成局部 lambda。重复引用的值使用局部 optional 缓存，
单次引用的值无需缓存；这些状态不进入 Model，也不跨拍保存。

分支条件先求值，所选分支随后按需求值。普通操作的输入按顺序准备，再执行操作。
未选分支中的除法、动态索引、断言和资源读取不会提前执行。局部复用限定在当前 value 求值区域，
不会跨状态操作发布复用；跨事务读取仍通过原有共享边界及读取快照机制处理。
因此生成计算块的数量由可达数据节点及引用关系决定，不随分支路径数量反复复制。

布尔需求分析在单个分析对象达到 100,000 个节点或 memo 条目时放弃继续展开。
可选的事实证明可以跳过；主需求分析使用同一有界按需生成路径继续编译，不拒绝合法程序。
`cpp/lowering.json` 记录条件环、需求预算回退、局部计算块与局部缓存数，供验收和诊断使用。
这些是静态生成计数，不代表每周期执行次数。

## 验证

通用回归位于 `pycircuit/tests/test_field_projection.py`，覆盖字段独立性、嵌套字段与更新、
显式断言和生产者约束、条件环及预算回退。递增深度的用例检查生成规模，并以 sanitizer
验证未选中的除零路径；已有 Signal/EHR/Queue 测试继续核对读取时机、背压和原子取消。

Ripes5 的对照脚本支持完整 Control、直接标量以及 `control.field` 参数；完整验收使用标准
程序清单和检查器，保留独立预期及原生 Ripes 差异分类。详见[修复报告](../examples/ripes5/results/field-analysis-2026-10-15.md)。
IR 解释执行与真正 RTL 仿真分开报告；代码变小不作为动态速度提升的证明。

# 编译阶段的设计意图

本文记录分析和转化需要保留的语义，不规定具体算法。目标表示见 [ACIR 基础设计](../../acir/basic-design.md)，当前实现见 [ACIR v6](../acir.md) 和 [ACPy 前端](../../acpy/spec.md)。

## 1. 静态展开

确定实例、资源、初始化、端口和固定连接的身份。共享实例保持同一份状态，分别构造的实例保持独立。运行时分支不改变资源结构。

## 2. 类型与访问角色

区分组件引用和普通 payload SSA 值，保留位宽、数据结构和输入角色。消费性 Queue 参数的实际 payload 读取对应 pop；普通观察和 guard 不消费。按外层事务与实际资源合并重复消费，不消费未执行路径。

## 3. 计算与控制流

保留实际 SSA 来源、分支、短路和循环。Work 中的共享计算保留一份定义，通过参数关联到使用它的 Rule。状态读取不能为了共享而移出受保护路径，也不能通过重新读取另一阶段的状态复刻原值。

## 4. 事务边界

Rule 建立原子边界，Module 和 Method 不建立独立事务。跨 Module 的 Method 调用仍归入调用者的外层 Rule。Rule 返回的资源效果与显式写入一起提交或取消。

## 5. Guard 传播

Module 选择路径、Rule guard 和实际调用的 Method guard 共同约束事务，分支中的要求只作用于对应路径。Module 调用只读 Method 后，其 guard 沿返回值的数据和控制依赖传播到使用者，不阻塞无关 Rule。失败不等同于分支条件为假。

普通 SSA 值不增加持久 valid 状态，也不默认使用旧值。后续 lowering 必须保护相关计算的求值。

## 6. 组件契约与可见性

使用组件提供的 guard、效果、顺序和可见性推导事务关系。基础组件集中提供默认语义，用户组件显式声明契约。Queue 内部容量 EHR 属于组件实现；用户 EHR 的端口根据 Method 关系分配，不由任意 Rule 排序增加可见性。

Signal 保存初始化值与保留值。set → get 保留写者判断先于读者的顺序，但不要求写者成功；没有有效写入时读取保留值。同事务的临时效果保持整体提交或取消。

## 7. RuleGraph 与共享计算

从实际 IR 建立条件化访问摘要、准备计算关联及 Rule 顺序，保留资源、调用和推导来源。多个 Rule 可以使用同一计算，独立调用不能被无条件合并。图是派生分析结果，相关 IR 改变后更新或重建。

静态共享关系不等同于运行时共享求值；跨 tick 缓存仍需要独立的失效机制。

## 8. 优化、重载与诊断

保存的程序应在没有 Python 源码和旧分析图时独立重建依赖。优化必须保留事务、状态视图和条件执行边界。可确认的矛盾与无法证明的关系分别诊断，报告对应资源、调用和位置。

当前实现仅编译和分析，不包含执行后端或运行时缓存。具体支持范围见 [编译器使用说明](../README.md)。

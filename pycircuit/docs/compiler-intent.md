# 编译阶段的设计意图

语义依据 [核心设计](core-design.md)，进度和验证依据 [路线图](compiler-roadmap.md)。
array 的迁移目标依据正式的 [array 设计](array-design.md)：高层保留结构，按静态关系保守排序，进入 RTL 友好层再展开。

1. 静态展开 class Module 的 __init__；存在 __call__ 时绑定其固定连接。只提供公开 Rule 的实例
   无需主体或额外调用，不能自动调度其 Rule。实例、组件、类型和初值均进入源 MLIR。
   输出组件由父 Module 明确声明，赋值连接直接绑定 Rule 效果；删除 .outputs 和隐式输出构造。
2. 保留统一 Rule 的 guard／body、实际 SSA 来源、控制流和声明关系；局部值／参数优先于同名成员。
   参数、局部绑定及合流后的绑定以 NameLoc 保存名称和作用域，helper 展开附加 CallSiteLoc。
   名称不参与折叠、CSE、路径证明或资源身份判断；独立事务 MLIR 重载仍能恢复语义名称。
   Source IR 先做后端无关的别名、常量及结构分支归一化；Module 的静态事务调用点保留。
   事务提取直接解释 scf.if 的区域与合流，不把调用路径重复附加到每个参数和局部值。
   源绑定只命名最终结果，新增的索引、界限、就绪和效果条件使用用途名称。
3. 根据直接组件效果和嵌套调用推导只读／修改分类，按 Module 中修改性调用点建立独立事务。
4. 沿实参、控制和数据依赖传播读取就绪条件。失败不进入 else；分支要求不约束未执行路径；
   合流后的无关事务不继承分支局部失败。普通值不能跨独立事务传递效果性结果。
5. 嵌套操作共享外层原子 fire。按真实资源／路径合并消费，保留全部有条件效果和输出省略。
6. 在 MLIR 中传播组件／Rule 契约，分配固定 EHR 端口，保存分支后继和无环节点合并图。
   声明顺序不等于仲裁优先级，不引入未声明可见性。共享读取的前序写依赖传播到所有使用者。
7. 事务 IR 保留逻辑资源数组、动态坐标、选取域和候选固定端口；顺序分析枚举可能访问的资源。
   独立资源展开 pass 供 RTL lowering 使用；事务 IR 解释执行和 C++ 直接支持索引访问。
   RTL lowering 将读取／效果化为组合选择器、完整 fire、写使能、current／next-state。
   Queue 用旧队头及同拍腾空间的容量视图；Signal 用组合有效性；EHR 选择最高前序成功写端口。
   事务与 RTL 转换后复用清理 pipeline，折叠聚合构造／字段读取及合并重复计算，不改变事务和状态视图。
   共享结构值按使用次数保留，不依赖名称决定是否拆字段。布尔条件简化验证部分计算和共享读取的需求路径；
   断言提为 fire 的显式条件化检查依赖后，才可用其成功值简化就绪逻辑，RTL 继续承接相同依赖。
8. 独立 C++ lowering 按事务使用范围、共享边界和条件需求建立语句；emitter 只读取 MLIR 和 lowering 结果。
   Module 层级、组件数组、payload 字段与 Rule 名称进入生成代码；局部绑定与简单匿名表达式分别声明／内联。
   潜在非法计算保留实际选择／短路条件；共享块只在边界缓存本拍结果及固定读取视图。
   完整 fire 和所有效果参数求值后才发布状态操作，每拍按公共静态 schedule 执行并统一提交状态。
9. 直接读取 MLIR 的通用逐拍执行器分别以 IR 解释执行验证事务与 RTL 友好层。对照独立 ISA／模型预期、定向周期、
   优化开关和各阶段独立重载。JSON 仅用于报告，永不参与编译。

不实现自动仲裁、SystemVerilog、激活调度或跨拍缓存。可确认的不兼容与保守证明限制分开记录；
不能以额外状态视图、临时旁路或改写模型行为绕过核心契约。

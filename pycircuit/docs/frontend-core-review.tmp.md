当前前端仍有重复表达、失效处理分支和语义校验缺口。收紧表达核心应先确定合法语法与接口边界，再统一内部表示，最后简化编译处理；事务条件、共享读取、组件契约和 EHR 可见性仍需完整保留。

本文汇总源码检查和临时目录中的最小复现。此前 31 项回归及示例验收覆盖既有模型，不能据此推断本文涉及的其他前端表达都已正确实现。本文的结构统计不等于性能测量。

## 表达核心候选

以下是供讨论的边界，不是已经决定的新规范。

- `__init__` 构造资源和子实例，绑定静态配置与实例依赖。
- `__call__` 绑定组件端口，表达共享组合计算和每拍 Rule 选择；输出目的地由父 Module 预先声明。只提供状态和公开 Rule 的 Module 可以省略主体。
- `@ac.rule` 承载 guard、状态操作和原子事务。普通返回值用于计算；组件返回类型声明绑定输出的效果。
- 普通 helper 只接受 payload 并产生普通计算结果，不接收组件或 Module 引用，不隐式访问运行时状态；guard 可以观察状态，再把 payload 传给 helper。
- 定宽标量、struct、定长 payload array 和 tuple 构成普通值类型。组件引用与普通 payload 在类型检查中明确区分。
- 普通值按类型和位宽匹配，不提供通用类型转换调用或隐式截断、扩展；字面量依目标类型确定宽度。必要的位操作另行定义。
- 赋值、字段更新和短路等语法糖统一展开到同一套核心操作。不支持的表达直接诊断，不静默忽略。

需要保留的能力包括共享状态、嵌套原子调用、独立事务入口、条件化多输出、动态选择已有 Queue 数组元素，以及 Signal 和 EHR 的不同可见性语义。

## P01 固定连接与运行时分支

最小复现：

```python
def __call__() -> None:
    if False:
        out = stage()
```

当 stage 内的 Rule 返回 7 并递增计数器时，第 0 拍仍得到 `out=[7]`、计数器为 1、该 Rule 的 fire 为 True。父路径没有约束子 Module body 的执行。

相关处理：`Frontend.connect` 为子实例单独生成 body；事务提取的 `runBody` 以无条件路径进入各 body。

结论：允许外层 if 选择子 Module 本拍的执行。实例与端口连接保持静态，运行时条件递归传播到内部各 Rule 的完整执行条件；不创建 Module 级原子事务。

源 MLIR 保留控制流中的 module.call，事务提取从顶层入口沿调用位置递归进入子 body，携带路径值及路径有效性，替换所有 body 无条件执行的方式。子事务的 fire 合并父调用条件、自身 guard 和实际操作就绪条件。

外层条件可以来自其他 Module 的公开只读 Rule。传递既有 SSA 值及有效性，保留读取来源、固定 EHR 端口及前序写入依赖；不能复制或迁移读取来改变视图。读取失败不进入 else，合流后的无关事务沿原有规则执行。

首版保留每个实例一个固定 __call__ 连接点，不接受在不同分支为同一实例声明不同端口连接。

## P02 普通返回值与组件输出

两个最小复现都能编译执行：

```python
@ac.rule
def read() -> ac.u32:
    return 7

def __call__() -> None:
    out = read()  # out 是已声明的 Queue
```

```python
@ac.rule
def produce() -> ac.queue[ac.u32]:
    return 7

def __call__() -> None:
    state = produce()  # state 是已声明的 Cell
```

前者把普通返回值变成 Queue 输出事务；后者把 Queue 输出写入 Cell。`Lower.assignment` 检查调用角色和 payload，但没有充分验证 Rule 声明的组件输出类型。

结论：普通返回值与组件输出严格区分。Module 主体中的组件赋值是输出接口绑定，必须由声明的组件返回类型提供，完整匹配目的地的组件种类和 payload 类型。普通 u32 返回值不能隐式升级为 Queue 输出，Queue 输出也不能绑定到 Cell。

Rule 内的组件赋值是实际状态效果；允许 `out = read()` 将普通 payload 写入 Queue，与嵌套 read 的求值、guard 和容量要求同属外层原子事务。需要在主体连接输出时，可以定义组件返回类型的 producer Rule，或调用显式向已声明 Queue 写入的 send Rule。

普通返回值继续用于只读计算或同一事务内的计算，不能跨独立修改事务传值。赋值的类型匹配遵守 P15，不通过隐式类型转换绕过接口约束。

## P03 链式输出绑定

最小复现：`a = b = produce()`，其中 a、b 是两个已声明 Queue，produce 返回 Queue 输出。

实际第 0 拍为 `a=[]`、`b=[7]`。同一调用的 `output_binding` 属性被后一次赋值覆盖，未形成两个效果，也没有报错。

结论：禁止链式组件输出赋值。多输出使用声明明确的 tuple，每个输出槽位绑定一个目的地。如需广播，显式定义相应 Rule 效果。

尚待讨论：链式普通局部赋值是否也一并禁止，以减少语法表面积。本次确认仅覆盖组件输出绑定。

## P04 普通 helper 的状态修改

未装饰的成员 helper 可以写 Cell，并在外层 Rule 中执行成功：

```python
def helper() -> None:
    state = state + 1

@ac.rule
def action() -> None:
    helper()
```

这不是原子性失败，但它使状态修改同时存在于 Rule 和普通函数两套表达中，与“普通 helper 是组合计算”的描述不一致。

结论：普通 helper 只接受 payload 并产生普通计算结果，不接收 Cell、Queue、Signal、EHR 或 Module 引用，也不隐式读取、写入或捕获运行时状态。可以引用静态常量；运行时输入通过普通 payload 参数显式传入。

状态操作统一在 Rule 或 guard 中表达。guard 仍可观察状态，并把读出的 payload 交给 helper 计算；helper 不因被 guard 调用而获得访问状态的特权。

现有 OoO 的 free、issuable 等直接读取成员状态的未装饰函数需要迁移：把状态读取放入 guard 表达式或只读 Rule，普通 helper 只处理显式输入的 payload。迁移保留读取就绪条件和原有视图。

## P05 条件表达式的类型

最小复现：`if 2: state = 7`。实际条件为 False，state 不变。

原因是条件被隐式 cast 到 bool，而当前 bool 转换按位宽截断，2 的低位是 0。`if`、短路和条件表达式等路径均需统一检查。

结论：条件表达式必须为 bool，不做隐式整数到 bool 转换。if、条件表达式的 cond、guard，以及 and、or、not 的布尔操作数统一校验；分支内的普通 payload 计算不受此限制。整数条件可通过显式比较表达，例如 `count != 0`。

结合 P15，删除通用 `bool(value)` 转换写法；非零条件使用明确比较，不增加隐式真值或截断规则。

## P06 定长数组的形状校验

最小复现：`ac.cell[ac.array[ac.u32, 2]](initial=[1])`。

该声明能编译执行，状态实际只有一个元素。定长数组类型与初值形状不一致；后续访问第二个元素可能才暴露错误。

建议：在构造及 MLIR 验证中校验数组长度、嵌套形状和元素类型。独立重载 MLIR 也必须受同样约束。

待讨论：短初值是否一律报错？如果需要填充，应提供一种明确的构造表达，而不是隐式补齐。

新方案：不继承旧 array 初始化设计。统一使用 `ac.array(T, shape=(...))`，完整初始化及 shape 校验按正式的 [array 设计](array-design.md)执行。

## P07 内建调用的参数校验

原复现 `ac.u32(q.peek(123, ignored=456), 999)` 把两类非法调用混在一起。它能执行并读到正常队头，peek 的全部参数及 cast 的多余参数被静默忽略。该表达不是合法声明语法，也不是需要保留的功能。

拆开后的接口边界：

| 表达 | 含义与要求 |
| --- | --- |
| `q.peek()` | 合法的无参数队头观察 |
| `q.peek(123)` | 非法，多余位置参数必须报错 |
| `q.peek(ignored=456)` | 非法，未知关键字必须报错 |
| `ac.u32(value)` | 当前的显式类型转换，不是声明；已决定按 P15 删除 |
| `ac.u32(value, 999)` | 非法，多余位置参数必须报错 |

`ignored` 只是复现故意取的非法关键字名，没有特殊含义。

结论：删除对非法、多余参数的静默接受。内建调用按明确接口统一校验数量、关键字、重复参数和类型，不支持的参数直接报错。正常 peek 不属于这个缺陷；通用类型转换按 P15 删除，不因为它过去属于接口就继续保留。

## P08 Module 实例依赖的绑定

OoO RegisterFile 仍有空 `__call__(rob: ReorderBuffer)`，顶层仍需 `rf(rob)`，仅用于向 operand Rule 提供 rob。

当前实现已经能通过 `RegisterFile(rob)` 在静态构造时绑定此实例依赖。在临时副本中将 rob 移入 RF 构造参数并删除空主体后，32 拍 fire 和状态与原模型完全一致，事务与 RTL 执行器也一致。

另一个接口限制：给 Rule 直接传 Module 实例，如 `capture(storage)`，目前会报内部 `AttributeError: 'Instance' object has no attribute 'type'`，而非清晰的语言诊断。

结论：允许构造时绑定已经存在的实例依赖，也允许通过 __call__ 在构造后绑定固定接口。不能强制所有依赖都在 init 中绑定，否则无法表达相互引用。

编译器先构造实例并收集全部静态绑定，再展开主体和 Rule，避免按连接顺序立即展开而读取尚未绑定的另一方。实例和端口关系保持静态；P01 的调用路径条件另行传播。

实例引用或连接成环可以允许，例如反馈经过 Cell 或 Queue 跨拍运行；实际 Rule 调用无限递归或同拍执行依赖成环必须诊断。

没有绑定或执行选择用途的 Module 仍可省略 __call__，不要求额外调用。给 Rule 直接传 Module 参数是否纳入核心接口尚待讨论，内部 AttributeError 应至少改为明确诊断。

## P09 类型别名与序列类型

`ac.ref[T]` 仍被解析为 `ac.queue[T]`，最小复现确认它会消费 Queue；`ac.var[T]` 被直接解析为 T，同时还支持 `ac.var[T](value)` 的转换表达。前端类型解析也接受 vector 和 qarray。

结论：删除 `ac.ref[T]` 和 `ac.var[T]` 类型别名，以及 `ac.var[T](value)` 转换写法，不保留旧语法兼容。组件引用使用明确的组件类型，例如 `ac.queue[ac.u32]`；普通 payload 直接使用其类型，例如 `ac.u32`。普通局部变量和 SSA 计算能力继续保留，不需要 var 包装。

新方案统一使用多维 array，删除旧 vector、qarray 及旧 array 的专用设计，不保留兼容路径。内部数组结构在源及事务 MLIR 中保留，仿真直接解释，到 RTL lowering 再展开；详见正式的 [array 设计](array-design.md)。

## P10 Queue 数组的构造方式

当前有三套专门处理：

```python
ac.array(ac.queue[T], shape=(N,), ...)
[ac.queue[T](...), ac.queue[T](...)]
[ac.queue[T](initial=...) for i in range(N)]
```

建议只保留一种规范构造方式。收紧前应确定它是否覆盖按元素初始化、不同配置和空初值等必要能力，不能仅删除语法而丢失资源表达能力。运行时按下标选择已构造 Queue 的能力继续保留。

新方案：旧 Queue 数组专用构造被统一的多维 array 取代。元素可以是 payload、组件或 Module 引用，静态构造与实际存储语义分别由上下文及元素类型确定；详见正式的 [array 设计](array-design.md)。上述旧写法不作为兼容接口保留。

## P11 文件级组件构造

`Frontend.global_value` 仍可尝试构造文件级组件。以文件级 Cell 为最小复现，前端接受后，MLIR 编译报 SSA 支配错误。

结论：资源与子实例只能在 Module 的 __init__ 静态构造中创建，禁止文件级组件和 Module 实例构造。文件顶层保留导入、Module 和 payload 类型定义、普通 helper 和静态常量。

每个组件有明确的实例归属；多次实例化形成独立状态。需要共享时，在父 Module 中构造一份，再通过固定接口或实例依赖显式连接。删除全局资源惰性构造、额外归属推导和相关兼容路径。

文件级静态 payload 构造属于常量表达，不是硬件组件构造；允许哪些常量表达形式可另行明确，不因此重新允许文件级硬件状态。

## P12 嵌套函数和 Rule 声明

`Lower.statements` 仍处理函数声明及局部 guard 捕获，但没有形成完整的嵌套定义接口。最小复现中，Rule 内声明另一个带状态修改的 Rule，编译成功而该声明被忽略。

结论：禁止函数主体中的嵌套函数声明，包括在 __init__、__call__、Rule 和 helper 主体内定义函数。Rule 固定声明在 Module 类层级；普通 helper 在文件或 Module 类层级声明，并遵守 P04 的 payload 约束。非法声明直接报错，不静默忽略。

已声明的 Rule 和 helper 之间的嵌套调用继续支持，Rule 调用保留外层原子事务语义。清理嵌套声明及局部 guard 捕获路径时，保留合法 guard 表达式及 payload helper 调用。

## P13 未迁移的测试模型

[tests/models/transfer.py](../tests/models/transfer.py) 仍有返回内部组件的旧主体和 `state()` 包装调用。它现在不能编译，也未被现有回归实际使用。

结论：清理过时测试模型和旧表达，不为旧模型保留兼容路径。有独立覆盖价值的语义按已确认核心表达重新建立测试并纳入验收，其余旧内容删除。修正此前“所有示例和测试已迁移”的范围描述。

## P14 动态循环的接受范围

字面量固定循环可以静态展开；不能展开的 range 循环会生成循环 CFG 或 scf.while，之后事务提取拒绝循环 CFG，不能完成有限 RTL lowering。

这是当前能力限制，不能仅凭它判定实现是旧前端兼容代码。

结论：首版只接受静态循环，循环次数及展开结构必须在编译时确定并完成有限展开。不支持依赖运行时状态的循环次数，不保留只保存动态循环源 IR、随后必然无法完成 lowering 的兼容路径。

不能静态展开的循环尽早明确诊断，删除原有运行时循环 CFG 构建与循环序列化分支。循环体仍可包含合法运行时条件；循环结构静态不要求其中的数据和分支条件都是常量。

## P15 通用类型转换与位宽匹配

现有前端支持 `ac.u32(value)`、`bool(value)` 及其他标量类型调用，并可通过 `Lower.cast` 在参数、赋值等位置进行隐式转换。这些能力不能仅因实现已有就视为核心设计要求。

结论：删除通用类型转换调用和宽松隐式转换。普通值要求类型和位宽匹配；字面量根据目标类型确定宽度，与运行时值转换分开处理。

整数截取、补零和符号扩展可能只涉及连接选择，但仍会改变数据含义。需要这些能力时，以明确的位操作定义，不通过通用 cast 承载；具体位操作语法及完整规则尚待讨论，不先增加新接口。

同样的收紧原则适用于核心设计没有要求的额外表达和参数。删除前区分明确缺陷、重复语法和必要表达能力；数组事项继续暂缓，核心事务及状态可见性语义继续保留。

## O01 失效元数据和处理分支

源码检查得到以下清理候选：

- 前端生成的实例 `members`、`inputs` 元数据为空，但序列化器仍从 members 推导资源归属和输出 instance 操作。
- 模型头 `exports` 始终为空；它与仍在使用的共享 SSA export 操作不是同一机制。
- `Lower.imported` 有 `external:` 字符串身份路径，当前前端没有对应生产路径。
- 序列化器有 `array.update` 映射，当前前端使用统一 update 操作。
- `Value.consume` 的创建默认值为 False，当前没有设为 True 的生产路径，却仍保留传播及比较逻辑。实际 Queue 消费由调用上下文和操作 role 表达。
- `model.acir.mlir` 是 source 产物的同内容别名。

清理应按生产路径和读取路径逐项确认。`acir.export/external` 共享 SSA、资源身份与访问路径信息仍然有效，不能按相近名称一起删除。

结论：按生产和读取路径确认用途，删除失效字段、兼容分支和重复产物别名。MLIR 阶段产物统一为 source、transaction、RTL，不保留 model.acir.mlir 同内容别名。

资源归属、固定绑定、共享 SSA、访问上下文、契约及状态可见性等必要信息继续由明确的 MLIR 操作、类型、SSA 和 region 承载，不用旧兜底路径，也不因删除元数据而丢失这些语义。

## O02 Rule 和 helper 定义复用

`Frontend.behavior_call` 每次调用都会重新生成函数。OoO 模型生成 64 个函数，按实例、原定义和函数类别统计为 53 组；CPU 的同一 RF read Rule 也有多个定义副本。

根据定义、实例、静态绑定和捕获接口确认定义能否复用，把动态输入作为 SSA 参数。上述 53 组只是结构统计，不证明所有同组函数都能直接合并。

必须保留独立调用点、事务入口、契约调用上下文和 EHR 视图。复用函数定义不等于合并两次调用，也不能把不同读取视图的计算做错误 CSE。

结论：分别复用同一 helper 或同一实例下相同静态绑定的 Rule 定义，不把 Rule 与 helper 合成统一功能。helper 仍是只处理 payload 的普通函数；Rule 保留自身入参约束、guard、body、契约和状态效果。

每次调用保留实参和执行上下文，修改性独立调用点继续形成独立事务。不同实例的状态身份不能混淆；按调用点 lowering 仍保留读取视图和路径。定义复用不是硬件执行单元共享，也不是合并调用或事务。

## O03 控制流表示的转换

目前控制流经过 Python CFG、序列化器尝试恢复 SCF、失败则保留 CFG，随后事务 pass 又执行 SCF 到 CFG 转换。序列化器为此计算后支配关系、识别循环并处理回退；事务提取也进行 CFG 路径分析。

结论：源层以结构化控制流为规范，前端直接生成 scf.if。静态循环先展开，返回值及条件化输出通过 SSA 合流表达；后续需要 CFG 时统一使用 MLIR 标准转换，删除前端从自建 CFG 恢复 SCF 及失败回退的双路径。

规范化多处 return 和 None 输出必须保留实际执行路径，不提前求值原本不会执行的计算或效果。短路、读取失败不进入 else，以及合流后的无关事务不受失败读取阻塞等语义保持完整；标准控制流转换不能替代这些事务有效性分析。

## 编译简化的边界

输出绑定可统一为一次明确的类型检查与绑定构造，避免通过扫描 SSA 生产者及函数列表反推接口，再回填调用属性。

普通计算中的移位、除法和余数目前经内建函数声明，再由事务提取恢复标准算术操作。它们是后续检查候选，但不能直接归类为过时兼容；删除前需核对常量折叠、除零、移位范围和未执行分支的求值语义。

以下处理是核心设计所需，不列为删除候选：

- 完整 fire 条件和实际路径的就绪传播。
- 嵌套调用的原子效果及重复 Queue 消费合并。
- 满 Queue 同拍 pop 为 push 腾空间、新数据下拍可读。
- Signal 本拍 data 和 valid。
- EHR 固定端口、声明关系和共享读取的前序写入依赖。
- 分支顺序边合并后的节点级无环约束。
- 两层执行器和独立预期之间的逐拍验证。

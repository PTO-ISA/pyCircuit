pyCircuit RTL Building-Block / XPU Design Matrix v0.2

目标：建立可以拼装 CPU、GPU、NPU 和统一 XPU tile/cluster 的 RTL 积木库。每个条目都是可独立复用的 Verilog/SystemVerilog module、micro-block 或 composition shell。

本版范围：只关注 RTL 积木的功能、参数、端口、协议、时序和依赖关系；不把软件栈、ISA、编译器或功能验证作为设计矩阵的组成部分。

统一描述原则：Operation × Data Format × Microarchitecture × Domain，并增加 Interface Contract / Composition Role / Source。

Level定义例子
L0 Primitive最基本 RTL building blockadder / mux / reg / FIFO / arbiter
L1 Compute Block可独立复用的运算单元FP FMA / dot product / reduction / exp

重要原则：Matrix 的一行代表一个可寻找、可复用的 RTL 积木。真正进入数据库时，再拆成精确 Design Point，并必须绑定 canonical ports、clock/reset、protocol、latency/throughput、parameter legality 和 dependency closure。软件接口和功能验证不属于本版准入条件。

14. CPU / GPU / NPU / XPU 拼装关系

本节给出 RTL 层面的最小拼装配方。它不规定软件或 ISA，只规定哪些硬件积木必须有明确连接关系。

CPU tile

Fetch / Decode → Issue + Scoreboard → Integer / FP / SIMD units
                         ↓
                 Register File / Rename
                         ↓
             LSU → TLB/PTW → L1 Cache → Coherence
                         ↓
                    Tile Shell → NoC

GPU tile

Command Queue → Warp Scheduler → SIMT Stack / Active Mask
                                      ↓
                  Vector RF → Vector ALU / SFU / Tensor unit
                                      ↓
       Coalescer → Shared Memory / Bank Arbiter → DMA / NoC

NPU tile

Command Queue → Tiler / Address Generator → Local DMA
                                      ↓
       Weight Buffer / Activation Buffer / Scratchpad
                                      ↓
      MAC / Dot Product → PE / Systolic Array → Accumulator
                                      ↓
                  Quantize / Requantize → Tile Shell

XPU cluster

Host Bridge → Command Queue → Dispatch / Tile Scheduler
                                  ├─ CPU Tile ─┐
                                  ├─ GPU Tile ─┼→ Network Interface → NoC Router
                                  └─ NPU Tile ─┘                 ↓
                             Shared L2 / Coherence → Memory Controller
判断标准：当每个 tile 都能通过 Tile Shell 暴露统一的 command、stream、memory、event 和 clock/reset 端口，并能接入同一个 NoC/共享内存接口时，才可以称为 XPU RTL 组合，而不只是模块集合。

Dataflow有基础MediumP0
Memory / RF有基础HighP0
CPU µarch无HighP1
GPU SIMT无HighP1
NPU无CriticalP0/P1
LLM Operators无CriticalP1
DMA / Interconnect基本无CriticalP0/P1
XPU Integration / Composition新增CriticalP0
结论：原有 runtime 主要覆盖 L0 primitive 的一小部分；同时，原矩阵对把 compute block 连接成 tile/cluster 的 fabric、coherence、command 和 shell 积木描述不足。v0.2 将这些组合层单独列为 XPU-01～XPU-20。

16. RTL 积木优先级

不按“抓到多少 .v/.sv 文件”衡量进度，而按能否覆盖一个可拼装 tile 的关键路径排序。每个目标都可以从多个开源仓库寻找候选实现。

P0：先形成可连接的最小 XPU fabric

  1. Command Queue / Dispatch
  2. Tile Scheduler
  3. Ready/Valid FIFO / Skid
  4. RR / QoS Arbiter
  5. Stream MUX/DEMUX/Fork/Join
  6. Stream Crossbar
  7. Address Decoder
  8. AXI/TileLink Bridge
  9. Outstanding Tracker
  10. Stream↔Memory Bridge
  11. 1D/2D DMA
  12. NoC Router / Network Interface
  13. Shared L2 / Coherence Filter
  14. Atomic / Fence Unit
  15. Tile Shell
  16. Integer ALU / MUL / MAC
  17. FP FMA / SIMD Lane
  18. Dot Product / Systolic PE
  19. Banked RF / Scratchpad
  20. Reduction / Prefix Scan

P1：扩展 tile 的能力边界

补充 TLB/PTW、L1 cache、branch predictor、GPU SIMT stack、shared-memory banking、quantization/sparsity、3D DMA、ECC SRAM、格式转换和更完整的 FP/SFU 单元。

Existing Primitive Reuse

已有 add / mux / FIFO / async FIFO / CDC / memory 不要求重写，优先作为公共积木接入统一的 port/protocol 契约，再补充外部实现的 architecture variants。

# M6-02: incremental execution and source-unit scale baseline

Status: done for this bounded macOS-arm64 packet. Accepted: 2026-10-01. Started: 2026-10-01. Baseline: `477beae8` on
`codex/gfsim-source-units`, clean at dispatch.

This packet measures the current approved C3 source-unit build route. The
measurement tool/report are developer evidence, not installed interfaces or a
new product schema. No source/IR/runtime/ABI or caching guarantee is introduced.
Performance ceilings and simulation parallelism are outside this packet.

## Workload and claims

- Shared-definition axis: 1/16/64 leaf instances, exactly three Python source
  producers and two implementation translation units (leaf plus root).
- Distinct-source axis: 1/8/32 leaf sources, U+2 producers and U+1 implementation
  translation units; each source retains its own body/interface and CPP group.
- Explicit Python module/rule declarations are generated by a host fixture
  generator. There is no handwritten IR or whole-design capture/splitting.
- Actual Ninja executions distinguish source compile, link, each emit target,
  C++ TU compilation, model linkage and runner invocation. Static graph output
  is used only to verify declared dependencies, never as executed work.
- Timings are command wall-clock values, including startup. No-op startup is
  not compiler work; a three-cycle runner timing is not simulation throughput.
  RSS is not measured. No timing assertions or complexity/performance guarantees.
- No-op preserves bytes and mtimes. Single-leaf edits preserve independent
  unit artifacts, with conservative parent/link and complete emit invalidation
  recorded honestly. Type/interface edits and dedicated toolchain-stamp changes
  measure broader invalidation without touching shared compilers/install files.
- Every C++ size runs a literal per-instance observation/result oracle. Both
  targets emit for every case; the largest distinct case has required actual
  Verilator build/run and the same independent oracle.

## Verified build-graph defect under C3

The public counter example's old custom commands did not declare `.d` or the
full generated receipt inventory as byproducts. Ninja clean left payloads and
removed receipts, so the next public driver correctly rejected the incomplete
publication instead of rebuilding. The example also omitted compiler/helper
and toolchain dependencies.

The bounded correction declares exact owned byproducts and compiler dependencies.
Publication controls remain outside clean outputs. The preparation helper first
preflights the complete tree, rejects symlink/special entries without mutation,
returns a successful whole-tree no-op for populated regular files, and prunes
only wholly empty directory trees bottom-up. CMake owns file deletion; no recursive
payload deletion or force mode is added to publication.

A second defect appeared when generated Verilog CMake consumed paths with spaces:
Verilator 5.044 serialized JSON list elements into unquoted CMake text. Generated
CMake now temporarily quotes those elements during `verilate()` and restores
the package helper afterward. Independent tests build and run the emitted bundle
in-place with both source and build directories containing spaces, with no copied
bundle workaround. This is build integration under C3, not backend semantic logic.

Unicode generated-source/build directory names remain a separate local Verilator
5.044 issue: its JSON octal escapes fail parsing before list handling. This packet
does not claim arbitrary Unicode host-directory support; SourceOwner/name
legalization and M6-01's moved Unicode installation prefix are distinct claims.

Independent review rejected the first frozen candidate on Python 3.12: directly
running the preparation helper imported `pathlib`, which allowed the sibling
`types.py` to shadow the standard library. The bounded repair uses `os.path` and
`os.lstat`, preserves lexical parent traversal for symlink preflight, and retains
the same empty-tree/populated-tree behavior. The example regression pins its CMake
helper interpreter to the test interpreter rather than silently choosing another.

## Scope and coherence

The proposal reuses approved C1/C2/R1 semantics and explicitly identifies the new final projection, record reset dictionary, value-operand widening, required-record relation attribute and helper-origin acceptance. The read/get/create relation table has an independent source-extraction point and actual-SSA checks; it neither executes nor replaces numeric proofs, existing use targets, effects or scheduling. Canonical constructor references remain provenance-only after executable helper removal, with explicit standalone-final trust limits.

Both backends use the same verified declaration/state/value representation and derived leaf layout. A record retains one StateID, one D/E and one no-fail transfer. The proposed array payload conforms to the current SimDFFE no-throw copy-assignment requirement. The generated native record declaration is explicitly distinct from packed RTL layout and model ABI. Source-owned headers/groups, authority, supplied-unit rejection, name collision handling, output preservation and rollback boundaries are covered.

The slice excludes record ports, nonempty static parameters, collection shape, multi-writer records, SYSTEM/EXPECT B, typed DUT and new queue/runtime APIs. The proposal's tests independently specify old-Q/proposal/Xfer/reset values and common-verifier rejection cases; no execution is claimed.

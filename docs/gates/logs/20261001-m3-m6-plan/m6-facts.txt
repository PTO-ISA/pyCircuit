## Accepted baseline and boundaries

- M6-01 is accepted for its bounded macOS-arm64 packet at product baseline
  `d351079b`. It covers replacement crash recovery across compile/link/both
  emits, five reachable first-publication compile interruptions, recovery
  interruption, lock behavior, and moved-prefix clean-environment execution.
  Its own boundary says first-publication of final programs and generated
  bundles remains open, and Linux/Windows plus actual parallel simulation are
  not claimed. See [M6-01](../docs/work-items/m6-publication-relocation.md:3)
  and its [accepted evidence](../docs/gates/logs/20261001-m6-process-relocation/README.md:1).
- M6-02 is accepted for macOS arm64 at baseline `477beae8`. It measured six
  source-unit scale cases, deterministic rebuilds, no-op, leaf/type/toolchain
  invalidation, both emits and an actual distinct-32 RTL run. The report says
  edits conservatively re-emit all generated files and rebuild all C++ targets;
  RSS, throughput, and parallel simulation were not measured. It records a
  Verilator 5.044 Unicode generated-source/build-directory limitation and makes
  no arbitrary Unicode path claim. The accepted run's shared-64 compile/link and
  CPP build were 0.577/0.706 seconds; distinct-32 compile/link, CPP/RTL emits,
  and CPP model build were 2.164/1.107/1.114/6.151 seconds, with four jobs and
  process startup included. They are host observations, not thresholds. See
  [M6-02](../docs/work-items/m6-incremental-scale.md:3)
  and [measurement evidence](../docs/gates/logs/20261001-m6-incremental-scale/README.md:1).
- M7-01 is accepted for a local macOS 26/arm64 preview at `4584ad0b`. The
  support profile remains portless root, default clock, empty static arguments,
  and serial simulation. The semantic lane passed 311 tests while explicitly
  deselecting the two V44 scheduling/reordering cases. Its local wheel was tagged
  macOS 26; Linux/Windows and formal macOS 15 minimum are not proven. No stable
  release was published. See [M7 acceptance](../docs/gates/logs/20261001-m7-preview/README.md:1).
- Approved C3-C already defines the driver, source-unit ownership, publication
  journal/recovery protocol, single Runtime ABI, and SDK contracts. The exact
  approval record authorizes implementation within those bytes and says new
  interface changes still require approval. See [C2/C3 approval](../docs/rfcs/migration/approvals/c2-c3-foundation.md:14).
- C2-R1/M1 is also approved. It specifies isolated per-worker proposal buffers,
  join/check/barrier before Xfer, no source scheduling API, and serial Xfer as
  the initial valid implementation. Real parallel Xfer needs evidence for
  disjoint owners and a full-tree observation barrier. See
  [C2-R1 parallel boundary](../docs/rfcs/migration/c2-r1-unified-register.md:232)
  and [approval](../docs/rfcs/migration/approvals/c2-r1-m1-interface.md:1).
- M3 remains use-case driven: choose one concrete workload, close only its
  required approved capability, and leave unrelated backlog visible. FIFO,
  memory/CDC, multi-domain, four-state, external typed DUT and complete
  SYSTEM/EXPECT B still need separate design/approval. See [M3 plan](../docs/development/pycircuit-modernization-plan.md:264)
  and [capability ownership](../docs/work-items/migration-capabilities.md:25).

## Concurrent ownership and stop boundaries

- PM freezes the candidate; unit-test authors own only their fixtures/tests;
  one implementation owner per importer/pass/runtime/build-generator file.
  ACIR ODS/registry, root CMake, CMake presets and release workflow each need a
  single integration owner.
- Per-platform runs use independent current-checkout build/install directories.
  Never share compiler prefixes across jobs, copy artifacts between worktrees,
  or let CI matrix jobs mutate the same output directory.
- M6 measurement logs and outputs stay in fresh `.pycircuit_out/<packet>/`
  directories. A change to the workload, measurement parser or build graph
  invalidates its corresponding baseline/report binding.
- Stop and request the required design/user review if implementation needs a
  new source/IR/CLI/runtime/schema/ABI/error/timing/ownership contract, a new
  public support promise, a scheduler/user control, or an external version/tag/
  publication action. Existing approved C1/C2/C3/R1/M1 semantics authorize no
  silent expansion beyond their exact frozen text.

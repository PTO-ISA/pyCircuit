# RV32I core design contract

The example's [NDF workflow](https://github.com/PTO-ISA/pyCircuit/blob/codex/rv32i-core-demo-20261102/examples/rv32i_core/spec/README.md) is the
entry point for its reviewable design input, specification and acceptance.

- [Design input](https://github.com/PTO-ISA/pyCircuit/blob/codex/rv32i-core-demo-20261102/examples/rv32i_core/spec/design-input.md): architectural
  authority, selected EEI, five-stage goals and observable correctness.
- [Core specification](https://github.com/PTO-ISA/pyCircuit/blob/codex/rv32i-core-demo-20261102/examples/rv32i_core/spec/core-spec.md): ISA/EEI,
  finite state owner and transaction, interfaces, stages, dependencies, flush,
  precise effects, reset/trap and shared execution policy.
- [Acceptance criteria](https://github.com/PTO-ISA/pyCircuit/blob/codex/rv32i-core-demo-20261102/examples/rv32i_core/spec/acceptance.md): named
  independent checks and source/test relationships.
- [Usage](https://github.com/PTO-ISA/pyCircuit/blob/codex/rv32i-core-demo-20261102/examples/rv32i_core/README.md) and
  [results](https://github.com/PTO-ISA/pyCircuit/blob/codex/rv32i-core-demo-20261102/examples/rv32i_core/RESULTS.md): public commands and actual
  implementation evidence with its selected scope.

These NDF 0.2 revision-1 clauses remain draft until reviewed. This page is a
navigation entry rather than a second normative explanation. Build, simulation
and mapped-cell results do not approve a specification or certify an ISA.

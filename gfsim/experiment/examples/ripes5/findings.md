# Ripes5 依赖驱动的 Signal 简化：验收与耗时

2026-10-02，aarch64，同一机器／Python 3.11.16。从固定提交 `56fe061` 保存源码和基线后，将阶段重复的组合计算集中为两个 Queue 派生 Signal，并删除五阶段的定时自唤醒。初始化之后的 Work 激活由实际读取资源的变化通知驱动。旧 Python、新 Python、固定版本原生 Ripes 的 13 程序 × 4 配置全部逐拍一致，共 11,316 行（包含第 0 拍）；原有 48 组占 3,096 行，长循环四组占 8,220 行。

[results.json](results.json) 保存源码、参考二进制、轨迹散列和行数；[timing.json](timing.json) 保存正式测速的全部样本。可重现命令、构建说明及逐拍接口见 [README.md](README.md)。

## 实现与代码量

五个阶段仍是普通类，每条 Rule 明确保留 begin、propose 和 complete。Fetch／Decode 读两个 Signal；Execute 只提交 `ex_result.next_slot`。Memory／Writeback 保留原业务逻辑。始终非空的寄存器 Queue 使用自动登记读取的 `peek()`；气泡仍由 `Slot.valid` 表示。

`peek()`／`Signal.value` 自动登记实际读者，`propose_revise()` 自动登记目标 Queue 依赖。提交改变 Queue 时，引擎通知实际读者并安排下一 tick 的 Work；Signal 结果变化也走同一通知机制。阶段没有显式 `request_wakeup`。同值 revise 不通知，输入与目标稳定时省略重复计算；store 和退休事件的序号在实际发生时递增，重复写入同值的事件仍保留。

`model.py` 新增两个通用 Signal、两个普通 helper 和精确的 module_queues／module_signals／signal_queues 绑定。两个 helper 各自读 Queue，不读 Signal。`logic.py` 新增固定不可变 `ExResult` 记录和可复用的 load-use 纯函数。阶段 Rule 不再调用 EX 组合函数；外部快照仍使用纯值控制函数，第 0 拍不初始化 Signal、不推进时钟。

按物理行计数，含空行和注释；模型总计为三个运行时文件，不含测试、工具、文档及两版共用且未变的 ISA／记录／引擎：

| 文件 | 56fe061 | 简化后 | 变化 |
| --- | ---: | ---: | ---: |
| stages.py（五阶段） | 257 | 168 | −89（−34.6%） |
| model.py（连线和观测） | 103 | 129 | +26 |
| logic.py（值类型和纯函数） | 87 | 100 | +13 |
| 模型总计 | 447 | 397 | −50（−11.2%） |

新增的 `evidence.py` 和 `worker.py` 是对照／测速工具，不进入模型行数。没有修改核心调度器、仲裁、原版 Ripes 或比较器，也没有隐藏缓存、手动补唤醒、直接状态修改、新基类或 Signal 子类。

## 正确性与观测

原有 12 个程序保持原来的周期与退休边界。新增 `memory_loop_256`：256 次 `lw → add → sw` 和条件分支，256 次 load-use、256 次 store，2,054 拍、最终数据 `[3, 768]`；旧／新模型的四配置均先与原生轨迹逐拍比对，之后才测速。

全部对比覆盖初始化、流水 valid／PC、stall／flush、前递选择、PC mux、寄存器、全部数据、store 和退休事件。只按原比较器剔除原生 `raw` 诊断字段，没有周期移动或放宽比较。MEM 前递优先于 WB、WB→ID 旁路、enable 优先于 clear、停顿时旧 EX 继续前进，以及固定版本 JALR 行为均保持。

全量回归 `RIPES5_REQUIRE_NATIVE=1 python3 -m unittest discover -s gfsim/experiment -v`：52 项全部通过，零跳过，16.127 秒。包括引擎、原有 CPU、Signal、review，以及新增长循环断言、逐拍 Signal 求值上界、EX 仅在 Signal 上下文执行，以及所有唤醒必须带有变化资源槽位的检查。

四份 `review-output/dependency-wakeup/after/array_sum/*.html` 由通用 ReviewTrace 生成，展示两个 Signal 的输入、求值和读者通知。测试确认每个 Signal 初始化一次、每次 Xfer 最多求值一次；开启观察器的全部行与未观察运行一致。初始化与首次 Xfer 可能同在第一个 review frame，计数分别标记。

## 身份、历史与剩余范围

原生 Ripes `5b8a616edcb6f0a2ddb07e78951348b72497f1e1`，VSRTL `8497dd14fe80e57efcff4c424a9a3b6363d93eb7`；完整源码／二进制 SHA256、Python 版本、主机、CPU affinity、输入散列及轮换顺序均记录在正式 JSON 中。

历史记录：`baseline.json` 是生成式写法重构之前的五次初步样本；`review-output/generated-style/` 是之前的 48 组对照；`review-output/migration/` 是参考路径迁移验证。它们不代表当前模型。上一轮保留五阶段定时自唤醒的 Signal 版本保存在 `review-output/simplification/`，其源码、报告及正式计时另保存在 `after-source/`；该版本的 52 组轨迹散列与当前版本完全相同。旧的“阶段自唤醒为必需”说明已修正。`review-output/simplification/before/preliminary-timing.json` 是本轮动手前旧工具的七次单程序计时，未绑定 CPU、未预热；上面的正式结果使用统一 worker 重新测量 `56fe061` 与当前源码。

本轮没有发现实现阻碍或需要修改框架的缺口。这个结论仅适用于当前寄存器 Queue + revise 表达：没有验证消费型队列、容量背压、可变访存延迟、完整 ISA、压缩指令、异常、系统调用或非对齐地址。保留固定版本 Ripes 对 JALR 的 ADD 行为，未作 ISA 修正。覆盖是有界程序验证，不是穷举证明。

# Example authoring and verification standard

An example teaches one component or an inseparable set of behaviors. Keep its
source, stimulus, independent expected behavior, README and existing CMake
integration together. Use the [current language profile](../docs/reference/language.md#transactional-frontend-replacement)
for admission and the [frontend guide](../docs/development/agent-frontend-guide.md)
for authoring. Retained legacy designs are migration inputs, not supported
patterns merely because they remain in the catalog.

## Sources and interfaces

Ordinary sources describe algorithm, state and connections. The compiler owns
storage, clock/reset, admission and atomic commit plumbing. Physical primitive
and independent-clock conformance examples retain their explicit test purpose;
they are not templates for ordinary designs.

Follow the guide's [Module interface](../docs/development/agent-frontend-guide.md#module-hierarchy-and-independent-outputs)
and [Rule cohesion](../docs/development/agent-frontend-guide.md#rule-authoring-contract)
contracts. Shared fields travel as a named Struct; independent interfaces use
tuple results and direct unpacking. One value stays scalar. Do not duplicate
compiler-owned resource guards or manufacture a validity wrapper for a Rule
that did not commit.

## Scenario and oracle

Prefer a short generated `@system` scenario with independently derived
assertions. Backend parity alone is insufficient: both targets can implement the
same mistake. Log-only examples can keep an `expected.json` trace beside the
source, checked by the shared verifier. Reuse mechanical compile/run helpers,
while each design or its
owning test supplies expected values, timing, ordering and failure behavior.

Add a custom host driver or RTL testbench only for a boundary that generated
Systems cannot exercise, such as independent clocks, Discard/retry or four-state
stimulus. Preserve existing boundary oracles until an equivalent owner is
identified and verified. Native/Verilator parity is not four-state RTL evidence.

A smaller teaching scenario does not validate a displaced long benchmark.
Preserve original frequency, depth, latency and independent checks in their
owning nightly/API tests. Record migrated, merged and retired coverage separately
from PASS, FAIL and NOT RUN. No example count is a delivery target.

## Documentation and registration

Each README explains component intent, stimulus, observable expectations,
run commands and known limitations. Candidate hashes, tool versions and past
run totals belong in gate evidence rather than permanent introductions.
The [catalog](catalog.json) and `examples/CMakeLists.txt` define registration;
[README.md](README.md) is generated by `tools/example_catalog.py navigation`.
Do not maintain separate numerical inventories in prose.

Published `GENERATED.md`/`GENERATED.json` excerpts must come from verified output
and retain their existing source/artifact receipts. They are documentation, not
an alternate implementation. Complete stage artifacts remain build outputs.
No additional sign-off management files are required for ordinary examples.

## Execution

Use `tools/run_examples.sh --tier gate|nightly`. Gate selects the explicit list
in `examples/CMakeLists.txt`; nightly includes the full registered inventory.
API contracts and compiler rejection tests run separately through
`tools/run_api_tests.sh`. See [testing and gates](../docs/development/testing-and-gates.md)
for commands and candidate reporting. Neither an archived fixture nor a catalog
entry is a passing run.

## Sampling and runner configuration

Native `sample()` exposes the last successful Work snapshot; Xfer commits state
without recomputing that snapshot. RTL testbenches must compare the equivalent
settled precommit observation, then advance the physical clock. A continuous RTL
output observed after the edge is a different observation, not evidence of an
extra native cycle. Keep the independent expected values and compare matching
phases; never shift traces to hide an actual latency error.

Runner JSON uses `"schema": "pycircuit-model-config"` and `"version": "1"`.
The version is a JSON string, not numeric `1`. Include a finite `max_ticks`.

## Simulation build profile

The standard example gate and `pycircuit run` build generated simulation code
with CMake Release optimization. Use the same optimized profile for complete
cycle workloads and timing comparisons. Keep all source checks and the declared
current scenario contract. Changing a tutorial cycle count requires explicit
new expectations plus preservation of any displaced long regression under its
real owner; compiler optimization alone is not permission to reduce coverage.
Manual generated-code builds may select Debug when debugging.
